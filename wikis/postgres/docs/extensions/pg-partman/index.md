# pg_partman

Automates creation and retention of time- or id-based partitions on top of PostgreSQL native declarative partitioning.

- **Type:** third-party — available on RDS, Aurora, Azure, Cloud SQL
- **Preload required:** Only for the optional `pg_partman_bgw` background worker
- **Repo:** <https://github.com/pgpartman/pg_partman>

👉 Full walkthrough: [Scaling → Partitioning → pg_partman complete setup example](../../scaling/partitioning/pg-partman/complete-setup-example.md)

---

## Install

```sql
CREATE SCHEMA IF NOT EXISTS partman;
CREATE EXTENSION IF NOT EXISTS pg_partman SCHEMA partman;
```

---

## Quick start (v5)

```sql
CREATE TABLE public.events (
    id          bigint GENERATED BY DEFAULT AS IDENTITY,
    created_at  timestamptz NOT NULL,
    payload     jsonb,
    PRIMARY KEY (created_at, id)          -- PK must include the partition key
) PARTITION BY RANGE (created_at);

SELECT partman.create_parent(
    p_parent_table => 'public.events',
    p_control      => 'created_at',
    p_interval     => '1 month',
    p_premake      => 4                   -- future partitions kept ahead
);

-- Retention: drop partitions older than 12 months
UPDATE partman.part_config
SET retention = '12 months',
    retention_keep_table = false
WHERE parent_table = 'public.events';
```

## Running maintenance

Maintenance creates new partitions and applies retention. It **must** run regularly — pick one:

=== "pg_cron"

    ```sql
    SELECT cron.schedule('partman-maintenance', '@hourly',
                         $$CALL partman.run_maintenance_proc()$$);
    ```

=== "Background worker"

    ```ini
    shared_preload_libraries = 'pg_partman_bgw'
    pg_partman_bgw.interval = 3600
    pg_partman_bgw.role = 'postgres'
    pg_partman_bgw.dbname = 'appdb'
    ```

## Useful queries

```sql
-- Config for all managed tables
SELECT parent_table, control, partition_interval, premake, retention
FROM partman.part_config;

-- Child partitions of a parent
SELECT * FROM partman.show_partitions('public.events');

-- Rows landing in the default partition = missing partitions!
SELECT count(*) FROM public.events_default;
SELECT * FROM partman.check_default();
```

## Gotchas

- v5 removed trigger-based partitioning and changed `create_parent` arguments (`p_type` defaults to `range`, no more `native`). Old v4 examples won't work as-is.
- Data in the default partition blocks creation of overlapping child partitions — move it with `partman.partition_data_proc()`.
- Unique constraints / PKs must include the partition key.
